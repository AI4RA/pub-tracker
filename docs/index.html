Pub Tracker

 Each PI's most recent paper, in one spreadsheet.
GitHub

Upload a spreadsheet of principal investigators. Pub Tracker looks up each one in OpenAlex, Semantic Scholar, PubMed, and ORCID, finds their most recent paper, and gives you an Excel file with the paper, its date, journal, and a link, plus a Google Scholar link to check each PI. Your file never leaves your browser and nothing passes through our servers; only names, institutions and ORCID iDs go straight to those public databases.

API keys (optional)

You don't need any keys. Pub Tracker works without them, and ORCID and Google Scholar never need one. Keys only matter for longer lists: a free key of your own raises that service's limits. Each key is sent only to the service that issued it.

Rough guide: with no keys, a list of up to about 50 PIs runs fine. For a few hundred, get an OpenAlex key (one minute). Request a Semantic Scholar key well in advance; approval can take weeks. In the meantime you can untick Semantic Scholar for big runs.

Session only. Keys are held in this tab's session memory, never saved to disk, and cleared when you close or reload the tab. You can also pass them in the address, as ?openalex=…&s2=…&ncbi=…&email=…; they are read once and removed from the address bar.

Data privacy

None of your data goes to our servers. We don't run any. Pub Tracker is a set of static files on GitHub Pages. Once the page has loaded, everything happens in your browser, on your computer.

What stays on your computer

  • Your uploaded file. It is read by your browser and never uploaded anywhere. Any columns other than name, institution and ORCID are never read or sent.
  • The results. The table and the Excel file are built in your browser and saved straight to your downloads.
  • Your API keys, if you add any. They are held in this tab's memory only and cleared when you close or reload it.

What is sent, and to whom

To look up a PI, your browser contacts the public scholarly databases you tick, directly, with no stop in between:

  • OpenAlex (api.openalex.org): the PI's name, or ORCID iD. Institution matching is done in your browser.
  • Semantic Scholar (api.semanticscholar.org): the PI's name.
  • PubMed (eutils.ncbi.nlm.nih.gov): the PI's name and institution.
  • ORCID (pub.orcid.org): the PI's name and institution, or ORCID iD.
  • Google Scholar: nothing, unless you click a PI's Google Scholar link yourself.

An API key or contact email you add goes only to the service it belongs to. These services see your network address, as any website you visit does, and handle requests under their own privacy policies.

What is not collected

  • No accounts, no cookies, no analytics, no tracking.
  • No server of ours, so there is no log of your lists or results to keep, lose, or share.
  • The only outside code is the SheetJS spreadsheet library, loaded from a public CDN when the page opens.

The names and institutions sent are the kind of information already public in faculty directories and published papers. Don't add other sensitive data to the upload; it is never used, so there is no need. You can check all of this yourself: the source code is public, and your browser's developer tools (Network tab) show every request the page makes.

How Pub Tracker works

Everything runs in your browser

Pub Tracker is a static website on GitHub Pages. There is no server of ours in the middle: your file is read in the browser, your browser calls each service directly, and the spreadsheet is built in the browser. The only things that leave your computer are each PI's name, institution and ORCID iD, sent to the services you tick, plus any API key you add, sent only to the service that issued it.

Finding the right person

  • ORCID is searched first, by name and institution. An iD tied to the institution is passed to OpenAlex and Semantic Scholar so they can match the exact person.
  • OpenAlex and Semantic Scholar search authors by name, then rank the candidates by how well the name fits, whether their affiliation matches the institution, and how much they have published.
  • PubMed searches the full author name together with the institution in the affiliation field.
  • When you give an institution, OpenAlex, ORCID and PubMed will not fall back to a namesake elsewhere: "not found" is better than the wrong person.

Picking the most recent paper

Each source reports the PI's newest paper dated on or before today; forthcoming issues with future dates are skipped. The newest of those wins. Sources that report the same paper (same DOI or title) are listed as agreeing.

  • High two or more sources agree, or the ORCID iD came from your file.
  • Medium one source, matched by ORCID or by name plus institution.
  • Low matched by name only. Check it.

Google Scholar

Google Scholar has no public API and refuses requests from other websites, and Pub Tracker sends nothing through a server of its own. So for Google Scholar, each PI gets a link to a profile search you can open with one click to check the result by hand.

The spreadsheet

  • Most recent paper: one row per PI, with the title linked to the paper, date, journal, DOI, the source that found it, the sources that agree, a confidence level, ORCID, and a Google Scholar search link.
  • By source: what each source found for each PI and how it matched, to audit a result.
  • About: when the file was made and how results were chosen.

About Pub Tracker

Pub Tracker finds the most recent publication for each PI on a list, from open scholarly databases, and returns it as a spreadsheet. It is built for research offices that need a quick, current snapshot of their investigators' publishing.

It is a partnership between Nathan Layman (University of Idaho), Stephen Wright (Idaho State University), and AI4RA.

Data sources

OpenAlex (CC0), Semantic Scholar, PubMed (NCBI E-utilities), and the ORCID public API. Each service's own terms apply to what it returns.
